Cómo se organiza el sistema

Interfaz. main.tsx monta App. HashRouter resuelve las pantallas; Shell compone navegación, arrastre, paneles y modales. Los componentes consumen stores Zustand y utilidades compartidas.

Estado y transporte. boardStore, routineStore, logStore y adminUsersStore usan api.ts. authStore usa fetch directamente. La API devuelve JSON; los avatares se envían como FormData. La interfaz refresca datos tras acciones; no se identificó un canal WebSocket.

Backend. urls.py resuelve rutas hacia vistas DRF. Las vistas aplican permisos y querysets; serializers validan y representan datos; el ORM opera sobre modelos. La autorización real corresponde al servidor, aunque RequireStaff también oculte una pantalla.

Persistencia local del navegador. authStore persiste sesión; pomodoroStore persiste tareas/temporizador; uiStore persiste solo el tema. Los demás stores mantienen estado en memoria.

Datos y despliegue

Relaciones. User → Board → Column / Card / Routine. Card → CardEvent / CardNote. Card tiene rutina opcional. LogEntry pertenece a User y referencia opcionalmente Card y Board. Las flechas de esta frase expresan agrupación; las FK se detallan al seleccionar models.py.

Producción declarada. Nginx sirve el build de React y reenvía API/admin a Gunicorn. El backend usa PostgreSQL del servicio db en Compose; media se comparte y Nginx lo sirve directamente. WhiteNoise atiende estáticos de Django.

Alternativa de configuración. settings.py selecciona PostgreSQL con DB_ENGINE=postgres; sin ello selecciona SQLite. Solo se describe el código: no se abrió ninguna base.

Límite de certeza. Docker/Compose describen una topología posible. No se comprobó el despliegue activo, TLS externo, variables de entorno, credenciales ni datos. Los enlaces a archivos son relativos a la carpeta docs del proyecto; la copia independiente conserva esas rutas, pero no contiene el código fuente.
